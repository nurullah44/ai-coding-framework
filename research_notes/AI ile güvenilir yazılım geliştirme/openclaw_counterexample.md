## Q1. His workflow in his own words (blog posts, talks, podcasts)

### Takeaway
In his own posts (June 2025 to Feb 2026), Steinberger says he runs 3–8 agents in parallel (Codex CLI with gpt-5-codex, later gpt-5.2-codex, as his main driver from about Oct 2025; Claude Opus powers the assistant itself). He commits straight to main without branches or worktrees and says "most code I don't read". He dropped big upfront specs as "the old way" in favour of planning by chatting with the agent. He treats tests as helpful but weak ("AI generally is bad at writing good tests"). He also openly calls the habit an addiction ("slot machine addiction"). — [Workflow, 2025-10-14](https://steipete.me/posts/just-talk-to-it/); [Workflow, 2025-12-28](https://steipete.me/posts/2025/shipping-at-inference-speed/); [Addiction account, 2025-08-19](https://steipete.me/posts/just-one-more-prompt/)

**"Just Talk To It - the no-bs Way of Agentic Engineering" (2025-10-14), verbatim:** — [Source](https://steipete.me/posts/just-talk-to-it/)
- "Agentic engineering has become so good that it now writes pretty much 100% of my code."
- Context (before OpenClaw): "I work by myself, current project is a ~300k LOC TypeScript React app, a Chrome extension, a cli, a client app in Tauri and a mobile app in Expo."
- Parallelism and git: "I’ve completely moved to codex cli as daily driver. I run between 3-8 in parallel in a 3x3 terminal grid, most of them in the same folder, some experiments go in separate folders. I experimented with worktrees, PRs but always revert back to this setup as it gets stuff done the fastest." / "My agents do git atomic commits themselves."
- On guardrails: "Yes, with claude you could do hooks and codex doesn’t support them yet, but models are incredibly clever and no hook will stop them if they are determined."
- Model: "I build pretty much everything with gpt-5-codex on mid settings."
- Cost: "I currently have 4 OpenAI subs and 1 Anthropic sub, so my overall costs are around 1k/month for basically unlimited tokens."
- Why he left Claude Code: "the absolutely right’s, the 100% production ready messages while tests fail - I just can’t anymore."
- "Blast radius": "If you throw multiple large bombs, it’ll be impossible to do isolated commits, much harder to reset if sth goes wrong."
- Plans: "I rarely use big plan files now with codex. codex doesn’t even have a dedicated plan mode - however it’s so much better at adhering to the prompt that I can just write “let’s discuss” or “give me options” and it will diligently wait until I approve it. No harness charade needed. Just talk to it."
- Specs: "Do you do spec-driven development? I used to back in June. Designing a big spec, then let the model build it, ideally for hours. IMO that’s the old way of thinking about building software." / "If it’s something tricky, I ask it to write everything into a spec, give that to GPT-5-Pro for review (via chatgpt.com) to see if it has better ideas".
- UI work: "I often start with sth simple and woefully under-spec my requests, and watch the model build and see the browser update in real time."
- Screenshots: "I’d say at least 50% of my prompts contain a screenshot."
- Refactoring ("But the code is slop!" section): "I spend about 20% of my time on refactoring. Ofc all of that is done by agents, I don’t waste my time doing that manually." His refactor list includes jscpd (duplication), knip (dead code), eslint plugins, "adding tests and code comments for tricky parts".
- Review: "/review (built-in, only sometimes since I have review bots on GH, but can be useful)".
- Tests: "Ask the model to write tests after each feature/fix is done. Use the same context. This will lead to far better tests, and likely uncover a bug in your implementation. If it’s purely a UI tweak, tests likely make less sense, but for anything else, do it. AI generally is bad at writing good tests, it’s still helpful tho, and let’s be honest - are you writing tests for every fix you make?"
- Agent file: "My Agent file is currently ~800 lines long and feels like a collection of organizational scar tissue. I didn’t write it, codex did, and anytime sth happens I ask it to make a concise note in there."
- Lint gate: "(If you don’t know or don’t use ast-grep as codebase linter, stop here and ask your model to set this up as a git hook to block commits)".
- Failure modes he admits: "Sometimes it refactors for half an hour and then panics and reverts everything, and you need to re-run and soothen it like a child".
- Closing advice: "Don’t waste your time on stuff like RAG, subagents, Agents 2.0 or other things that are mostly just charade. Just talk to it."

### Inferences
- His process changed fast. The June 2025 AI-authored conversation summary describes 500-line specs ("SDD"). By Oct 2025 he called big-spec-driven development "the old way". By Dec 2025 he said he no longer reads most code. OpenClaw's November-onward build overlaps that stated workflow period; this is not proof every OpenClaw change followed it. — [AI-authored summary, 2025-06-25](https://steipete.me/posts/2025/when-ai-meets-madness-peters-16-hour-days/); [First-hand, 2025-10-14](https://steipete.me/posts/just-talk-to-it/); [First-hand, 2025-12-28](https://steipete.me/posts/2025/shipping-at-inference-speed/)
- **Qualified inference:** his described controls include agent-written tests, review bots, refactoring and lint/hooks, but also his own design judgment, watching the code stream and reading selected key parts. The posts do **not** establish that no human review occurs or that every task lacks acceptance criteria. They do not publish a repeatable ticket-level acceptance template. — [Just Talk To It, 2025-10-14](https://steipete.me/posts/just-talk-to-it/); [Shipping at Inference-Speed, 2025-12-28](https://steipete.me/posts/2025/shipping-at-inference-speed/)
- He flagged the solo-developer scope ("if you work in a bigger team that workflow obv won’t fly"). OpenClaw's growth then required changed contributor/release processes, documented in the January and May project posts; his solo description must not stand in for the October team's workflow. — [2025-12-28 post](https://steipete.me/posts/2025/shipping-at-inference-speed/); [2026-01-29 announcement](https://openclaw.ai/blog/introducing-openclaw); [2026-05-05 admission](https://openclaw.ai/blog/openclaw-rough-week)
